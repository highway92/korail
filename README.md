# 코레일 개인 예매 도우미

**현재 0.12.0:** 0.11.3 전체 발권 성공을 사용자 환경에서 확인했습니다. 예매 경합 구간에만 대기 기본0초/상태 확인0.05초를 적용하고 Windows 입력 연결을 미리 열어 재사용합니다. 예약 화면 도착 후 기존 대기로 돌아갑니다. 실제 속도 개선 폭은 추가 실행의 inputMs/trace로 확인합니다.

**현재 0.11.3:** 조회 화면에서 시작 전 30초를 기다리던 회귀를 수정했습니다. 화면 도착 판정을 별도 모듈로 분리하고 Native 창 제목 반영 지연을 보완했습니다. 결제 화면의 열차·등급·좌석 비교 생략은 유지합니다.

**현재 0.11.2:** 결제 화면에서는 열차·등급·좌석 비교를 생략합니다. 저장 카드 입력과 결제/발권으로 바로 진행하고 중복 제출 방지 및 결제 완료 확인은 유지합니다.

**현재 0.11.1:** Windows 입력으로 실제 예약·결제 화면 이동이 확인됐습니다. 결제 대상 판별에는 화면 렌더링 대기, 인접한 번호/날짜 텍스트 처리, 항목별 불일치 진단을 보완했습니다. 실제 카드결제·발권까지의 성공은 아직 미확인입니다.

**현재 0.11.0:** 정상 조회되는 기존 Chrome에서 버튼을 찾고 Windows 마우스 입력으로 선택·예매·안내 확인·결제 버튼을 누릅니다. 로컬 연결은 [Windows 입력 연결 안내](native_input/README.md)를 따라 등록합니다. 설정창 실행은 Native Messaging 연결을 먼저 확인하며 실패하면 JavaScript 클릭으로 대체하지 않습니다. 카드 폼 입력 방식은 유지하며 카드정보를 마우스 프로그램에 전달하지 않습니다. 오프라인 검증과 실제 코레일 발권 성공은 구분합니다.

**0.10.6 입력 순서 비교:** 초점이 true인 상태에서도 search 전환 실패가 재현됐습니다. 조회 화면의 가격 선택·예매·안내 확인에 pointerdown/mousedown/focus/pointerup/mouseup/click 순서를 전달하도록 변경했습니다. 스크립트 이벤트는 여전히 isTrusted:false이며 실제 마우스 입력과 동일하다고 주장하지 않습니다. 누르는 과정에서 대상이 사라지거나 가려지면 남은 클릭을 강행하지 않습니다. 결제 페이지의 입력/제출 방식은 이번 비교에서 바꾸지 않았습니다. 단계 로그에 input과 clickDispatched를 추가했습니다. 오프라인 입력 순서/중복제출 검증은 통과했고 실사이트 원인은 아직 미확정입니다.


**0.10.5 초점 비교 시험:** 사용자 navigation 기록에는 start만 있고 focused:false, visibility:visible, userActivation:true였다. 이 기록은 새 창 차단의 증거가 아니다. 자동 예약 시작 직전 원래 코레일 탭과 창을 활성화하고 document.hasFocus() 및 visible을 확인한다. URL 이동이나 새로고침은 하지 않는다. 2초 동안 초점이 잡히지 않으면 source_focus_timeout으로 중단한다. 클릭 방식/횟수/대기는 그대로이며, 초점이 실사이트 실패 원인인지는 미확정이다. 시작 후 설정창보다 코레일 창이 앞으로 오는 것은 이번 시험의 의도된 동작이다.


**0.10.4 전환 진단:** 두 안내가 닫힌 뒤 search에 남는 문제는 여전히 미해결입니다. 타이밍/재클릭을 더 변경하지 않고 window.open 호출 결과(반환 없음/창 반환/예외), 폼 제출 이벤트, 페이지 이탈과 초점/사용자 활성화 상태를 기록합니다. 호출 인수·URL 쿼리·입력값은 기록하지 않습니다. window.open은 원래 인수와 반환/예외를 유지하고 실행 종료나 2분 후 복원합니다. 반환 null만으로 팝업 차단이라고 단정할 수 없습니다(noopener 등도 가능). 1건 시험 후 자동으로 펼쳐지는 진단의 `navigation` 부분으로 확인합니다. 새 창을 강제로 열거나 차단 설정을 변경하지 않습니다.


**최신 0.10.3:** 1건 실행에서 웹사이트의 active 가격 칸을 요구하던 조건을 제거했습니다. **현재 목록 불러오기 → 설정창에서 열차 한 편만 체크 → 현재 선택한 1건 예매·결제** 순서로 사용합니다. 허용 등급의 예약 가능한 지정석을 찾아 가격 칸 선택부터 실행합니다. 두 등급 모두 가능하면 해당 열차의 현재 선택 등급을 유지하고 없으면 일반실부터 선택합니다. 열차 미선택/복수 선택, 허용 등급 없음, 대상 사라짐, 좌석 없음은 서로 다른 오류로 표시합니다. 웹사이트에서 미리 가격을 클릭할 필요가 없습니다. 테스트 57개와 모의 실행으로 검증했으며 실사이트 성공은 미확인입니다.


**0.10.2 설정창 부팅 점검:** 사용자가 실행 상태도 나타나지 않는다고 확인했습니다. 모듈 초기화 실패를 별도 스크립트에서 감지하고 상단에 준비 완료/실패와 버전을 표시합니다. 초기화 완료 전 1건 실행 버튼은 비활성화합니다. 버튼 입력 수신과 업무 진행 상태를 구분합니다. 누락된 모듈을 모의로 만들어 로드 실패 표시와 버튼 비활성화도 검증했습니다. 실제 사용자 환경의 원인은 아직 확정되지 않았습니다. 갱신 후 상단에 ‘설정창 준비 완료 · 0.10.2’가 보이는지 먼저 확인합니다.


**0.10.1 진단 개선:** 상태 표시를 설정창 상단으로 옮겼습니다. 선택 좌석 읽기 오류 코드를 보존하고 예약 전 단계도 즉시 표시합니다. 선택 후 보조 클릭 기록 설치는 최대 1.5초만 기다리며, 주요 executeScript 호출은 10초 뒤 응답 시간 초과를 알립니다. 시간 초과는 이미 전달된 브라우저 작업을 취소하는 기능이 아니며 자동 재시도하지 않습니다. 사용자 보고의 시작 후 멈춤 원인은 아직 확정되지 않았습니다. 위 상태 문구와 단계 코드로 다음 확인 지점을 좁힙니다.


**최신 0.10.0 — 1건 흐름 시험:** 먼저 코레일 조회 목록에서 예약 가능한 일반실/특실 가격 칸을 하나 선택합니다. 설정창의 **현재 선택한 1건 예매·결제**를 누르면 저장된 카드로 선택한 열차의 예약·결제·발권 확인까지 실행합니다. 반복조회용 체크박스·우선순위·조회 간격은 이 경로에 사용하지 않습니다. 새로고침과 예약 목록 우회가 없고 예매는 한 번만 제출합니다. 단계·안내 확인 대기는 기본 0.8초이며 설정 가능합니다. 타이밍 차이 검증용 기본값으로, 실사이트 문제가 해결됐다는 의미는 아닙니다. 중간 예약 상세를 거치지 않고 결제 화면으로 직접 이동하는 경로도 대상 열차·등급·좌석 검증 후 진행합니다. 테스트 54개와 모의 단일 실행 검증을 통과했으며 실사이트 성공은 아직 미확인입니다.


**최신 0.9.6:** 미결제 예약이 예약 목록에 실제로 남은 화면이 확인됐습니다. 조회 화면 유지가 예약 실패라는 가정을 철회하고, 예매 재클릭 분기를 제거했습니다. 화면 전환 제한시간 후에도 조회 화면이면 `/ticket/reservation/list`를 한 번 열어 대상 날짜·열차·구간·시각이 일치하는 단일 1매 예약을 확인하고 그 카드의 결제/발권으로 진행합니다. 등급·좌석은 결제 화면에서 확정하고 최종 승차권과 비교합니다. 없거나 여러 건이면 새 예약을 제출하지 않고 중단합니다. 기존 예약을 자동 취소하지 않습니다. 별도 갱신 시험도 매크로 실행 잠금을 사용해 실행 중 새로고침을 막습니다. 원래 반복조회는 예약 전에 종료되므로 새로고침이 이번 원인이었다고 단정하지 않습니다. 테스트 52개와 모의 DOM 검증을 통과했으며 실사이트 연결 확인은 남아 있습니다.


**0.9.5 진단:** 자동 예매 호출 이후 연결편성 안내가 열리고 확인 후 조회 화면에 머무는 실사이트 문제는 미해결입니다. 버튼 클릭 순서를 비교하는 수동 진단을 추가했습니다. 확장프로그램 갱신 후 설정창에서 ‘직접 클릭 기록 시작’을 누르고 코레일의 확인·예매 버튼을 직접 조작한 뒤 ‘현재 단계 구조 읽기’의 `clicks`만 확인합니다. 조회 화면의 허용된 버튼에 한해 pointerdown/up/click, 실제 이벤트 여부, 태그·클래스와 순서만 최대 40개 기록합니다. 2분 후 수집을 종료하고, 입력값 및 결제·로그인 화면 조작은 수집하지 않습니다. 기록은 해당 탭의 임시 sessionStorage에 보관하며 읽을 때 만료된 기록은 삭제합니다. 자동 실행도 좌석 발견 후 같은 진단을 시작하므로 실패 후 직접 조작과 비교할 수 있습니다.

0.9.4에서 제공된 ‘동일한 예약 내역’ 안내의 **다른여정예약** 분기를 추가했습니다. 예약 상세와 결제 화면 직접 이동 모두 대상으로 검증하고 진행합니다. 51개 단위 테스트와 오프라인 DOM/진단 검증을 통과했지만 이는 실사이트 자동 예약 성공 확인이 아닙니다.


**0.9.3 진단 수정:** 0.9.2의 안내→예매 반복을 제거하고 안내 후 이어 누르기는 최대 한 번으로 제한했습니다. 클릭 대상은 제공된 파란 버튼 구조 `button.btn_bn-blue02.reservbtn:not(.path_button)`와 정확한 ‘예매’ 텍스트를 모두 만족해야 합니다. 클릭 반환 로그에 검증한 대상 정보를 추가했습니다. 실제 사이트에서 반복 안내의 원인은 아직 미확정이며, 수동으로 파란 버튼을 눌렀을 때의 결과와 비교가 필요합니다. 기존 버전의 반복 진행 설명은 대체되었습니다.


**최신 0.9.2:** 사용자 확인에 따라 연결편성 안내의 확인은 창만 닫는 것으로 처리합니다. 확인 후 같은 열차·등급을 재검증하고 예매 버튼을 누릅니다. 이 클릭으로 같은 안내가 다시 열리면 새 안내로 확인하고 진행합니다. 팝업이 닫히는 동안에는 확인을 중복 클릭하지 않으며, 새 안내 없는 대기 중에는 예매를 재제출하지 않습니다. 한 예약 단계에서 안내 확인은 최대 8회이며 화면 대기 제한도 유지합니다. 예약 화면 도달 시 추가 예매 클릭을 생략합니다. 48개 테스트를 통과했고 실사이트 재검증은 남아 있습니다. 아래 0.9.1의 대기만 하는 동작은 대체되었습니다.


**0.9.1 수정:** 예매 후 연결편성 안내를 확인하고 약 0.3초 만에 예매를 다시 누르던 분기를 제거했습니다. 실제 로그에서 이 재클릭 이후 같은 안내가 재등장했습니다. 이제 확인 후 설정된 화면 대기 제한(기본 30초)까지 예약 화면으로의 전환을 기다립니다. 지연 전환·전환 없음·안내 재등장을 포함한 테스트 46개를 통과했습니다. 실제 사이트 성공은 아직 확인하지 못했습니다. 아래 재클릭을 설명한 이전 버전 동작은 더 이상 적용되지 않습니다.


**최신 0.9:** 시작 시 이전 실행을 초기화하고 자동 예약·카드결제·발권을 항상 진행합니다. 복구 메뉴와 자동 진행 선택 옵션을 제거했고 팝업 뒤 일시적인 버튼 가림을 기다립니다. 테스트 47개와 오프라인 Chrome 검증을 통과했습니다. 실제 사이트에서 이번 수정은 아직 미검증입니다. [최신 사용법](extension/README.md)을 우선하세요. 아래는 이전 버전 이력입니다.

**이전 0.8:** 연결편성 안내 후 조회 화면에 남는 경로에서 예매를 한 번 이어 누르도록 보완했습니다. 카드 관리는 별도 탭으로 분리했으며 사용자 요청으로 로컬 평문 저장·자동 불러오기를 지원합니다. 개인정보 동의와 앱 발권은 항상 적용합니다. 회귀 테스트 41개와 모의 Chrome 검증을 통과했으며 이번 예매 분기의 실제 사이트 검증은 남아 있습니다. 아래 버전 설명보다 [최신 사용법](extension/README.md)을 우선하세요.

**이전 0.6:** 정상 Chrome 확장프로그램에서 시작 전 한 번 설정하고, 열차 감시부터 자동 예약·카드결제·발권 확인까지 이어 실행합니다. 모의 전체 흐름과 테스트 31개가 통과했으며 실제 코레일 전체 자동 결제는 미검증입니다. 알려진 화면 구조와 다르면 확인 코드와 함께 멈춥니다. [최신 사용법](extension/README.md)을 참고하세요. 아래 버전별 설명과 Python/Playwright 설명은 이전 구현 이력입니다.

**2026-10-04 진행 상태:** 확장프로그램 0.4에 선택적인 가격 선택·예매 1회 제출을 연결했습니다. 안내창·로그인·예약 상세에서 정지하며 모의 화면에서만 검증했습니다. 자동 카드결제·발권 검증은 아직 미구현입니다. 사용자 요청으로 카카오페이 대신 개인카드 직접결제를 구현할 예정입니다. 카드정보는 로컬 실행창에서 입력하며 기본적으로 실행 메모리에서만 사용하는 설계입니다. 아래 카카오페이 설명은 기존 Python 엔진의 설계 이력입니다. 최신 실행 범위는 [확장프로그램 안내](extension/README.md)를 참고하세요.

Windows 설정창 + 별도 Chrome 프로필 + Python/Playwright로 만드는 개인용 도구입니다.

**현재 개발 중입니다. 설정창과 공개 조회 이동까지 연결했고, 실제 열차 행·예약·카카오페이 화면 연결은 아직 검증 중입니다. 현재 버전은 예약이나 결제 요청을 제출하지 않습니다.** 거래 엔진의 테스트 통과는 실제 코레일 예매 성공을 뜻하지 않습니다.

## 정상 Chrome에서 목록 읽기 검증

Playwright 연결 환경에서 발생하는 조회 장애를 분리하기 위해 `extension` 폴더에 **Chrome 확장프로그램**을 추가했습니다. 정상 Chrome의 공개 목록 읽기와 1회 갱신은 사용자 스냅샷으로 확인했습니다. 0.3 버전은 별도 작은 설정창에서 간격·오류 재시도·종료 조건을 지정하고 선택한 열차의 좌석을 반복 확인합니다. 좌석을 발견하면 멈춥니다. 좌석이 없는 상태의 실사이트 반복 조회는 사용자 실행으로 확인했습니다. 실제 좌석 발견 시 정지는 아직 모의 화면에서만 검증했습니다. Tkinter와의 연결·예약 클릭·결제는 아직 포함하지 않습니다.

설치와 사용 순서는 [확장프로그램 안내](extension/README.md)를 참고하세요. `chrome://extensions`의 개발자 모드로 설치하며 F12 개발자 도구는 열지 않습니다. 시크릿 창이 아닌 일반 창에서도 사용할 수 있습니다.

## 실행

Chrome과 Python 3.12 이상이 필요합니다. 이 작업 폴더에는 `.venv`가 준비되어 있습니다.

- `run.cmd`를 더블클릭하면 설정창이 열립니다.
- 오류를 확인하려면 PowerShell에서 `./run.ps1`을 실행합니다.
- `전용 브라우저 열기`에서 코레일에 직접 로그인합니다.
- 탑승일·출발역·도착역을 입력하고 `조건으로 조회`를 누릅니다.
- 전용 브라우저에서 직접 검색한 경우 동일한 조건을 설정창에 입력하고 `현재 목록 읽기`를 누릅니다.

새 환경 설치:

```powershell
py -3.12 -m venv .venv
& .venv/Scripts/python.exe -m pip install -e '.[test]'
./run.ps1
```

## 설정

성인 1명, 편도 직통, 카카오페이를 대상으로 개발하고 있습니다. 일반실·특실은 기본으로 모두 허용하며 한쪽만 선택할 수 있습니다. 목록에서 여러 열차를 선택합니다. `직접 추가`는 출발 시각과 열차 번호를 알고 있을 때 사용하는 임시 입력 기능입니다. 날짜·구간을 바꾼 후에는 이전 대상을 그대로 사용할 수 없습니다.

선호 순서를 사용하지 않으면 예약 가능한 대상 열차를 같은 확률로 선택합니다. 한 열차에 일반실·특실이 모두 있어도 그 열차의 선택 확률이 두 배가 되지 않습니다. 선호 순서를 켜면 선택한 행의 위쪽부터 우선합니다.

조회 간격은 직전 조회 **완료 후** 다음 조회까지의 대기 시간입니다. 기본 10초이며 `실행 중 간격 적용`으로 탐색 중 변경할 수 있습니다. 상세 설정에는 페이지/요소 대기 제한, 클릭 후 대기, 예약 실패 대기, 오류 대기와 배수/상한, 연속 오류 제한, 최대 조회 횟수·탐색 시간·종료 시각, 결제 확인 간격·결제 대기·발권 확인 제한이 있습니다. 모든 시간 값의 단위는 초입니다. 빈칸으로 제한을 없앨 수 있는 항목은 화면에 표시됩니다.

결제 요청은 한 번만 보내고 휴대폰 승인 후 PC 확인을 반복하는 구조입니다. 대기시간을 600초보다 크게 설정해도 서비스의 10분 제한은 늘어나지 않습니다. 결제금액 상한은 두지 않습니다. 전화번호·결제 인증·비밀번호를 이 도구의 설정에 저장하지 않습니다.

## 저장 및 중지

신규 설정의 클릭 후 대기는 기본 2초, 조회 화면 진입 후 대기는 기본 10초입니다. `속도·재시도 상세 설정`에서 모두 변경하거나 0으로 끌 수 있습니다. 이전에 저장한 클릭 대기는 그대로 유지되므로 기존 설정에서 0초였다면 직접 변경하세요. 이 대기는 화면 준비 시간을 확보하는 기능이며 사이트의 조회 실패를 해결한다고 보장하지 않습니다.

설정과 거래 상태, 전용 브라우저 프로필은 `%LOCALAPPDATA%\KorailMacro`에 저장합니다. 중복 실행은 파일 잠금으로 차단합니다. 브라우저 프로필에는 로그인 정보가 포함될 수 있으므로 공유하지 마세요.

`일시정지`·`중지`·창 닫기는 진행 중인 브라우저 호출이 끝난 다음 처리됩니다. 중지는 기존 예약 취소나 환불을 수행하지 않습니다. 이미 제출한 거래의 결과가 불명확하면 새 예약·결제를 시도하지 않고 확인이 필요한 상태로 멈춥니다. 창을 닫아도 거래 기록은 유지됩니다.

개발 확인을 위해 `현재 목록 읽기`는 공개 조회 화면의 열차 결과 영역만 `search-rows.html`로 저장합니다. 로그인·예약·결제 화면은 저장하지 않습니다. 계정 전체 화면이나 결제 인증값을 진단 로그에 기록하지 않습니다.

## 검증

조회 중 HTTP 500 등의 실패를 확인하면 빈 목록을 운행 없음이나 매진으로 처리하지 않고 오류로 표시합니다. 실행 중인 구버전 창에는 변경이 즉시 반영되지 않으므로 다음 실행부터 적용됩니다. 현재 실사이트 조회 실패 원인은 조사 중입니다.

```powershell
& .venv/Scripts/python.exe -m pytest -q
& .venv/Scripts/python.exe -m tools.smoke_gui
```

자동 테스트는 설정 검증, 열차 선택, JSON 저장·실행 잠금, 거래 의도 선저장, 재시작/중복 방지, 재시도 간격, 작업 스레드 소유권을 검증합니다. GUI smoke 검증은 창을 잠시 만들었다 닫으며 예약·결제를 하지 않습니다.

실사이트 남은 검증: 열차 목록과 더보기 → 등급 선택 → 예약 및 안내 → 예약 식별 → 카카오페이 요청 → 미결제 안내 → 결제 완료 확인 → 발권 결과. 실제 화면을 확인한 단계만 순서대로 활성화합니다.
