## 정상 Chrome에서 목록 읽기 검증

Playwright 연결 환경에서 발생하는 조회 장애를 분리하기 위해 `extension` 폴더에 **Chrome 확장프로그램**을 추가했습니다. 정상 Chrome의 공개 목록 읽기와 1회 갱신은 사용자 스냅샷으로 확인했습니다. 0.3 버전은 별도 작은 설정창에서 간격·오류 재시도·종료 조건을 지정하고 선택한 열차의 좌석을 반복 확인합니다. 좌석을 발견하면 멈춥니다. 좌석이 없는 상태의 실사이트 반복 조회는 사용자 실행으로 확인했습니다. 실제 좌석 발견 시 정지는 아직 모의 화면에서만 검증했습니다. Tkinter와의 연결·예약 클릭·결제는 아직 포함하지 않습니다.

설치와 사용 순서는 [확장프로그램 안내](extension/README.md)를 참고하세요. `chrome://extensions`의 개발자 모드로 설치하며 F12 개발자 도구는 열지 않습니다. 시크릿 창이 아닌 일반 창에서도 사용할 수 있습니다.

## 실행

Chrome과 Python 3.12 이상이 필요합니다. 이 작업 폴더에는 `.venv`가 준비되어 있습니다.

- `run.cmd`를 더블클릭하면 설정창이 열립니다.
- 오류를 확인하려면 PowerShell에서 `./run.ps1`을 실행합니다.
- `전용 브라우저 열기`에서 코레일에 직접 로그인합니다.
- 탑승일·출발역·도착역을 입력하고 `조건으로 조회`를 누릅니다.
- 전용 브라우저에서 직접 검색한 경우 동일한 조건을 설정창에 입력하고 `현재 목록 읽기`를 누릅니다.

새 환경 설치:

```powershell
py -3.12 -m venv .venv
& .venv/Scripts/python.exe -m pip install -e '.[test]'
./run.ps1
```

## 설정

성인 1명, 편도 직통, 카카오페이를 대상으로 개발하고 있습니다. 일반실·특실은 기본으로 모두 허용하며 한쪽만 선택할 수 있습니다. 목록에서 여러 열차를 선택합니다. `직접 추가`는 출발 시각과 열차 번호를 알고 있을 때 사용하는 임시 입력 기능입니다. 날짜·구간을 바꾼 후에는 이전 대상을 그대로 사용할 수 없습니다.

선호 순서를 사용하지 않으면 예약 가능한 대상 열차를 같은 확률로 선택합니다. 한 열차에 일반실·특실이 모두 있어도 그 열차의 선택 확률이 두 배가 되지 않습니다. 선호 순서를 켜면 선택한 행의 위쪽부터 우선합니다.

조회 간격은 직전 조회 **완료 후** 다음 조회까지의 대기 시간입니다. 기본 10초이며 `실행 중 간격 적용`으로 탐색 중 변경할 수 있습니다. 상세 설정에는 페이지/요소 대기 제한, 클릭 후 대기, 예약 실패 대기, 오류 대기와 배수/상한, 연속 오류 제한, 최대 조회 횟수·탐색 시간·종료 시각, 결제 확인 간격·결제 대기·발권 확인 제한이 있습니다. 모든 시간 값의 단위는 초입니다. 빈칸으로 제한을 없앨 수 있는 항목은 화면에 표시됩니다.

결제 요청은 한 번만 보내고 휴대폰 승인 후 PC 확인을 반복하는 구조입니다. 대기시간을 600초보다 크게 설정해도 서비스의 10분 제한은 늘어나지 않습니다. 결제금액 상한은 두지 않습니다. 전화번호·결제 인증·비밀번호를 이 도구의 설정에 저장하지 않습니다.

## 저장 및 중지

신규 설정의 클릭 후 대기는 기본 2초, 조회 화면 진입 후 대기는 기본 10초입니다. `속도·재시도 상세 설정`에서 모두 변경하거나 0으로 끌 수 있습니다. 이전에 저장한 클릭 대기는 그대로 유지되므로 기존 설정에서 0초였다면 직접 변경하세요. 이 대기는 화면 준비 시간을 확보하는 기능이며 사이트의 조회 실패를 해결한다고 보장하지 않습니다.

설정과 거래 상태, 전용 브라우저 프로필은 `%LOCALAPPDATA%\KorailMacro`에 저장합니다. 중복 실행은 파일 잠금으로 차단합니다. 브라우저 프로필에는 로그인 정보가 포함될 수 있으므로 공유하지 마세요.

`일시정지`·`중지`·창 닫기는 진행 중인 브라우저 호출이 끝난 다음 처리됩니다. 중지는 기존 예약 취소나 환불을 수행하지 않습니다. 이미 제출한 거래의 결과가 불명확하면 새 예약·결제를 시도하지 않고 확인이 필요한 상태로 멈춥니다. 창을 닫아도 거래 기록은 유지됩니다.

개발 확인을 위해 `현재 목록 읽기`는 공개 조회 화면의 열차 결과 영역만 `search-rows.html`로 저장합니다. 로그인·예약·결제 화면은 저장하지 않습니다. 계정 전체 화면이나 결제 인증값을 진단 로그에 기록하지 않습니다.

## 검증

조회 중 HTTP 500 등의 실패를 확인하면 빈 목록을 운행 없음이나 매진으로 처리하지 않고 오류로 표시합니다. 실행 중인 구버전 창에는 변경이 즉시 반영되지 않으므로 다음 실행부터 적용됩니다. 현재 실사이트 조회 실패 원인은 조사 중입니다.

```powershell
& .venv/Scripts/python.exe -m pytest -q
& .venv/Scripts/python.exe -m tools.smoke_gui
```

자동 테스트는 설정 검증, 열차 선택, JSON 저장·실행 잠금, 거래 의도 선저장, 재시작/중복 방지, 재시도 간격, 작업 스레드 소유권을 검증합니다. GUI smoke 검증은 창을 잠시 만들었다 닫으며 예약·결제를 하지 않습니다.

실사이트 남은 검증: 열차 목록과 더보기 → 등급 선택 → 예약 및 안내 → 예약 식별 → 카카오페이 요청 → 미결제 안내 → 결제 완료 확인 → 발권 결과. 실제 화면을 확인한 단계만 순서대로 활성화합니다.
