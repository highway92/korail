# 코레일 목록 확인 — 확장프로그램 0.9

**0.9.3 진단 수정:** 0.9.2의 안내→예매 반복을 제거하고 안내 후 이어 누르기는 최대 한 번으로 제한했습니다. 클릭 대상은 제공된 파란 버튼 구조 `button.btn_bn-blue02.reservbtn:not(.path_button)`와 정확한 ‘예매’ 텍스트를 모두 만족해야 합니다. 클릭 반환 로그에 검증한 대상 정보를 추가했습니다. 실제 사이트에서 반복 안내의 원인은 아직 미확정이며, 수동으로 파란 버튼을 눌렀을 때의 결과와 비교가 필요합니다. 기존 버전의 반복 진행 설명은 대체되었습니다.


**최신 0.9.2:** 사용자 확인에 따라 연결편성 안내의 확인은 창만 닫는 것으로 처리합니다. 확인 후 같은 열차·등급을 재검증하고 예매 버튼을 누릅니다. 이 클릭으로 같은 안내가 다시 열리면 새 안내로 확인하고 진행합니다. 팝업이 닫히는 동안에는 확인을 중복 클릭하지 않으며, 새 안내 없는 대기 중에는 예매를 재제출하지 않습니다. 한 예약 단계에서 안내 확인은 최대 8회이며 화면 대기 제한도 유지합니다. 예약 화면 도달 시 추가 예매 클릭을 생략합니다. 48개 테스트를 통과했고 실사이트 재검증은 남아 있습니다. 아래 0.9.1의 대기만 하는 동작은 대체되었습니다.


**0.9.1 수정:** 예매 후 연결편성 안내를 확인하고 약 0.3초 만에 예매를 다시 누르던 분기를 제거했습니다. 실제 로그에서 이 재클릭 이후 같은 안내가 재등장했습니다. 이제 확인 후 설정된 화면 대기 제한(기본 30초)까지 예약 화면으로의 전환을 기다립니다. 지연 전환·전환 없음·안내 재등장을 포함한 테스트 46개를 통과했습니다. 실제 사이트 성공은 아직 확인하지 못했습니다. 아래 재클릭을 설명한 이전 버전 동작은 더 이상 적용되지 않습니다.


## 0.9 시작 시 초기화 / 항상 자동 발권 / 클릭 준비 대기

자동 예약·카드결제·발권은 항상 실행합니다. 관련 체크박스와 거래기록 복구 메뉴를 제거했습니다. 카드를 저장하고 열차를 선택한 뒤 **반복 조회 시작**을 누르면 이전 로컬 실행 기록·로그를 초기화하고 새로 시작합니다. 저장 카드와 최근 60초 재조회 횟수는 유지합니다. 실제 기존 예약이나 승차권을 취소하는 기능은 아닙니다. 다른 설정창에서 실행 중일 때는 기록을 초기화하거나 두 번째 실행을 시작하지 않습니다.

클릭 전 스크롤을 즉시 완료하고, 버튼이 가려져 아직 클릭하지 않은 경우에만 100ms마다 최대 3초 동안 다시 검사합니다. 실제 클릭이 반환되거나 통신 결과가 불명확한 경우에는 반복 제출하지 않습니다. 계속 가려져 있으면 `covered_action`과 가린 요소의 태그·클래스만 진단에 남깁니다.

업데이트는 Chrome 확장프로그램 관리에서 새로고침한 뒤 기존 설정창을 닫고 다시 열면 됩니다. 47개 테스트 및 오프라인 Chrome에서 중지→열차 추가→재시작, 팝업 후 가림 해제, 전체 모의 결제 흐름을 검증했습니다. 실제 사이트에서 이번 수정의 검증은 남아 있습니다. 아래는 이전 버전의 동작 이력입니다.

## 0.8 예매 안내 후 계속 진행 / 별도 카드 관리

사용자 실행 기록에서 예매 클릭 → 연결편성 이용안내 → 확인 → 조회 화면 유지가 확인됐습니다. 이 안내가 **예매 클릭 이후** 나타났고, 닫힌 뒤에도 같은 열차·등급이 선택되어 있는 경우에만 예매를 한 번 더 이어 누릅니다. 먼저 다음 화면으로 이동했으면 누르지 않으며, 일반 시간 초과에는 재클릭하지 않습니다. 추가 클릭 전에도 기록을 저장하고 두 번 이상 이어 누르는 루프는 만들지 않습니다. 이 분기는 재현 테스트를 통과했으며 실사이트 확인은 남아 있습니다.

설정창의 **카드 관리 열기**는 별도 탭을 엽니다. 카드 등록·수정·삭제는 그 화면에서만 합니다. 개인정보 수집·이용동의와 앱 발권은 사용자 요청대로 항상 적용하며 선택 옵션을 제거했습니다. 카드를 한 번 저장하면 실행 시 자동으로 사용하고, 설정창에는 끝 4자리만 표시합니다. 실행 중 카드 수정·삭제는 다음 실행부터 반영됩니다.

카드는 사용자 요청으로 이 Chrome 프로필의 확장프로그램 로컬 저장소에 **암호화 없이** 보관합니다. 잠금 비밀번호나 동기화·외부 전송 기능은 없습니다. 해당 프로필에 접근할 수 있는 사람은 저장된 정보도 볼 수 있습니다. 기존 암호화 보관함은 카드 관리의 ‘기존 암호화 카드 가져오기’에서 비밀번호로 한 번 가져오면 이후에는 비밀번호 없이 사용합니다. 저장 카드 삭제는 기존 암호화 보관함도 함께 삭제합니다. 카드정보를 거래/진단 기록에는 포함하지 않습니다.

업데이트 후 확장프로그램을 새로고침하고 기존 설정창을 닫아 새로 여세요. 실패 기록으로 실행이 차단되면 실제 예약·승차권 내역에 남은 거래가 없음을 확인한 뒤 기존 ‘중단된 거래 기록 복구’를 사용합니다. 아래 버전별 설명은 이전 동작 이력입니다.

## 0.7 빠른 반응·암호화 카드 보관함·중단 진단

새 창 기본값은 조회 완료 후 0.7초, 좌석 선택 후 0.1초, 화면 상태 확인 0.2초입니다. 설정은 계속 변경할 수 있습니다. 조회 대기는 최소 0.65초이며 같은 Chrome 프로필의 매크로 설정창과 1회 갱신 시험 전체에서 최근 60초 동안 목록 재조회 100회를 넘지 않도록 별도 잠금을 적용합니다. 실패한 재조회 시도도 횟수에 포함합니다. 수동 조회·다른 프로필·사이트 내부 네트워크 호출 횟수는 이 제한의 범위가 아닙니다. 이 수치는 사용자가 정한 상한이며 사이트의 허용 정책을 확인한 수치가 아닙니다. 기본 감시 제한은 6,000회 또는 2시간으로 늘렸습니다.

카드정보를 한 번 입력하고 보관함 비밀번호(10자 이상)와 함께 **암호화 저장**을 누르면 로컬 Chrome 프로필에 암호문만 저장합니다. 다음 실행부터 비밀번호 → **저장 카드 불러오기**로 입력을 복원합니다. 시작 이후에는 추가 비밀번호 입력이 없습니다. **저장 카드 삭제**는 보관함과 현재 설정창의 카드값을 삭제합니다. 비밀번호를 잊으면 복구할 수 없습니다.

보관함은 Web Crypto의 PBKDF2-SHA256(600,000회, 임의 16바이트 salt)로 키를 만들고 AES-256-GCM(매번 새 12바이트 IV)으로 암호화합니다. 암호화 키와 비밀번호는 저장하지 않습니다. 저장/복호화 실패 시 평문 저장으로 전환하지 않습니다. 잠금 해제한 뒤 실행 메모리 및 코레일 폼에 값이 존재하는 것은 암호화 저장과 별개입니다.

팝업 닫힘 애니메이션이 남아 있는 경우 같은 확인 버튼을 다시 누르지 않고 소멸을 기다립니다. 멈춤 기록에는 실행 단계와 페이지 전환/안내 처리/예매 클릭 반환 이력을 추가했습니다. 카드 값은 포함하지 않습니다. `timeout_reservation_from_search`이면 예매 요청 이후 예약 화면 대신 조회 화면에 남아 있었다는 의미이며 원인을 확정한 것은 아닙니다. 임의로 예매/결제를 반복하지 않습니다. **현재 단계 구조 읽기** 결과의 `execution`만 전달하면 이전 실행 경로를 확인할 수 있습니다.

### 0.6.1 팝업 처리 수정

좌석 선택으로 ‘서대전 정차’ 안내가 열려 예매 버튼이 가려지는 상황을 수정했습니다. 이제 선택 전후와 예매 이후 모두 팝업을 확인합니다. 조회 화면의 ‘이용안내’에 활성 확인 버튼만 있고 입력란·대체 선택지가 없는 일반 안내도 처리합니다. 매진·실패·결제·취소 등 상태 판단이 필요한 낯선 안내는 임의로 넘기지 않습니다. 동일 팝업 반복 또는 한 단계에서 8개가 넘는 안내에는 멈춥니다.

이전 실행의 거래 기록 때문에 시작이 막힌다면, 코레일 예약·승차권 내역에서 그 실행으로 남은 건이 없는지 먼저 확인합니다. 없음을 확인한 경우에만 설정창의 **중단된 거래 기록 복구**에서 확인 체크 후 **확인한 이전 기록 정리**를 누릅니다. 기존 기록을 보관한 뒤 새 실행 차단을 해제하며 실제 예약 취소나 결제를 수행하지 않습니다. 이미 예약·결제된 건이 있으면 다시 시작하지 말고 해당 건을 확인하세요.

## 0.6 한 번 시작해서 발권까지

1. 확장프로그램을 새로고침하고 설정창을 새로 엽니다. 코레일 로그인은 실행 전에 직접 합니다.
2. 원하는 날짜·구간을 성인 1명으로 조회하고 ‘현재 목록 불러오기’에서 대상 열차를 선택합니다.
3. **선택한 열차 자동 예약**, **예약 후 카드결제·발권까지 자동 진행**을 켭니다. 조회·재시도·종료 제한을 설정합니다.
4. 카드정보와 필수 동의·앱 발권 설정을 시작 전에 한 번 입력합니다. **반복 조회 시작**을 누르면 감시부터 발권까지 진행합니다. 입력 시험 버튼은 정상 실행에 필요 없습니다.

좌석 선택 → 예매 → 선택적 열차 안내 → 환불 안내 → 대상 예약/좌석/결제기한 대조 → 결제하기 → 카드결제 → 카드 입력 → 대상 및 입력값 재검증 → 결제/발권 1회 → 완료 안내 확인 → 해당 승차권 확인 순서입니다. 정상 흐름에서 사용자 클릭을 추가로 요구하지 않습니다. 카드정보는 실행 메모리에만 유지하고 완료·중지 시 참조와 설정창 값을 정리합니다. 코레일 페이지에 남은 입력값이나 브라우저 내부 메모리의 완전 삭제를 보장하는 기능은 아닙니다.

예약과 결제 제출 전 거래 의도를 기록합니다. 응답 불명확, 로그인 만료, 알 수 없는 안내, 대상 불일치, 저장 실패에는 자동 재제출하지 않습니다. 기존 거래 기록이 있으면 새 예약을 차단하며 자동 기록 삭제/재시작 복구는 아직 없습니다. 결제 대상이 1건인지도 확인합니다. 결제 후 승차권 화면 도착만으로 완료 처리하지 않고 날짜·구간·열차번호·출발시각·등급·호차·좌석을 대조합니다.

예약 후 화면 대기 제한, 동작 후 대기, 상태 확인 간격, 결제 후 발권 확인 제한은 설정 가능합니다. 초기 감시 기본 종료 조건은 여전히 3회·120초이므로 원하는 감시 시간에 맞춰 시작 전에 변경하세요. 실사이트가 알려진 구조와 다르면 확인 코드가 표시되며 그 지점에서 멈춥니다.

검증: 자동 테스트 31개 및 모의 Chrome 화면에서 시작 버튼 한 번으로 결제 1회와 발권 확인, 입력값 재사용/정리를 확인했습니다. 실제 코레일의 전체 자동 결제는 아직 검증하지 않았습니다. 예약/승차권 의미 기반 DOM 대조는 스크린샷을 기준으로 구현했으며 실제 DOM에 따라 조정이 필요할 수 있습니다. 아래 0.4/0.5 설명은 단계별 개발 이력입니다.

## 0.5 개인카드 입력 시험

사용자 제공 결제 입력 구조에 맞춘 **입력만 하기** 기능입니다. 아직 자동 결제 기능이 아닙니다. 확장프로그램을 새로고침하고 새 설정창을 여세요. 코레일 결제 화면에서 카드결제·개인카드를 선택한 뒤, 설정창의 ‘개인카드 입력’에서 값을 입력하고 ‘연결된 결제 화면에 입력만 하기’를 누릅니다. 화면에 도달하기 위해 새 테스트 결제를 만들 필요는 없습니다.

현재 지원 범위는 16자리 개인카드·일시불입니다. 입력란 15개의 구조와 주요 라벨, 연도 및 일시불 옵션이 일치해야 진행합니다. 할인 설정과 결제수단 저장 체크는 바꾸지 않습니다. 동의와 앱 발권 체크는 설정창에서 선택한 값으로 반영합니다. 결제/발권 버튼은 누르지 않습니다. 입력 성공은 DOM 값 유지 확인이며 카드사 인증 또는 승인 성공을 의미하지 않습니다.

입력 시도 후 설정창의 카드정보는 지웁니다. 성공하면 코레일 입력란에는 값이 남아 있으므로 해당 페이지에서 직접 확인하세요. 실패 시 입력값 삭제를 시도하지만 페이지가 바뀌거나 연결이 끊긴 경우 제거를 보장할 수 없어 직접 확인이 필요합니다. 입력값을 localStorage·거래 기록·진단에 넣지 않습니다. 모의 데이터로만 검증했고 실제 사이트의 보안 입력 모듈과의 호환성은 미검증입니다.

## 0.4 예약 연결 시험

확장프로그램을 새로고침하고 설정창을 다시 열면 **선택한 열차를 실제로 예약하기 (결제 전 정지)** 옵션이 나타납니다. 기본은 꺼져 있어 기존 좌석 감시만 동작합니다. 켜면 후보 발견 후 현재 날짜·역·열차번호·시각·승객 1명·등급·좌석 가능 여부를 다시 확인하고 가격 셀을 선택합니다. 선택 상태를 확인한 뒤 `button.reservbtn` 예매 버튼을 한 번 누릅니다. 좌석 선택 후 대기, 예매 후 대기 제한, 화면 확인 간격을 설정할 수 있습니다.

안내창·로그인·예약 상세를 만나면 멈춥니다. 자동 안내 확인, 로그인 후 자동 재개, 예약 내역 대조, 카드결제와 최종 발권 확인은 아직 미연결입니다. 실제 예약 요청을 발생시키므로 감시할 날짜·열차를 확인한 후 사용합니다. 실사이트 예매 동작은 미검증이며 모의 Chrome 화면에서 검증했습니다.

예매 제출 전 최소 거래 기록(대상 열차·등급·진행 상태·시각)을 확장프로그램 localStorage에 저장합니다. 값 저장에 실패하면 제출하지 않습니다. 같은 브라우저 프로필의 설정창끼리 예약 잠금과 기록을 공유합니다. 기록이 있으면 새 예약을 막습니다. 자동 기록 초기화는 제공하지 않으며 사용자의 실제 예약 상태를 확인하기 전 기록을 삭제하면 안 됩니다. 브라우저 프로필 간 잠금 공유는 지원하지 않습니다. 카드정보는 수집·저장하지 않습니다.

**현재 단계 구조 읽기**는 연결된 코레일 탭에서 짧은 JSON을 표시합니다. 화면 경로·허용된 버튼 문구/클래스·알려진 안내 종류와 결제 입력란의 태그·타입·ID·허용된 라벨만 읽습니다. 입력값, 본문 전체, 승차권 번호, QR/바코드, URL query는 포함하지 않습니다. 로그인 화면은 단계명만 표시합니다. 실제 결제 페이지의 구조를 확인할 때 카드정보를 입력할 필요가 없습니다. 이 버튼으로 나온 `actions`, `fields`, `notices`만 개발 대화에 전달하면 됩니다.

0.3.1은 할인 요금 좌석 인식을 수정하고 선택된 등급을 표시합니다. 진단 파일에는 열차 영역 외부의 보이는 ‘예매·좌석선택·운임요금·열차시각’ 버튼에 한해 태그·문구·클래스·비활성 여부를 추가합니다. 업데이트 후 선택 화면에서 목록을 다시 읽고 저장하면 하단 버튼 정보도 확인할 수 있습니다. 예약 동작은 아직 실행하지 않습니다.

정상적으로 조회되는 일반 Chrome에서 개발자 도구(F12)를 열지 않고 공개 열차 목록을 읽습니다. 별도 작은 설정창에서 반복 조회할 수 있으며 좌석 발견 시 멈춥니다. 예약·결제·외부 전송 기능은 아직 없습니다. Tkinter 설정창과 별도로 실행합니다.

## 0.3 반복 조회

1. `chrome://extensions`에서 확장프로그램을 새로고침합니다. 아이콘 팝업에 **0.3**이 보이는지 확인합니다.
2. 코레일에서 원하는 날짜·구간을 직접 조회합니다. 07:47과 08:20을 함께 찾으려면 07시 이후로 조회합니다.
3. 해당 탭에서 확장프로그램 아이콘 → **반복 조회 설정창 열기** → **현재 목록 불러오기**를 누릅니다.
4. 감시할 열차를 선택합니다. 일반실·특실은 기본 모두 허용합니다. 선호 순서는 비우면 동일 가중치이며, 사용할 경우 선택한 열차번호를 모두 쉼표로 나열합니다.
5. 조회 간격, 목록 대기 제한, 오류 추가 대기·배수·상한, 연속 오류 제한, 최대 갱신 횟수·실행 시간을 설정하고 **반복 조회 시작**을 누릅니다. 첫 시험 기본값은 10초 간격·3회·120초입니다.
6. 좌석 발견, 설정 제한 도달, 중지 또는 조건 변경 시 멈춥니다. 설정창 아래에서 결과를 확인합니다.

설정창과 연결된 코레일 탭을 열어 두어야 합니다. 팝업 아이콘 창은 닫아도 되지만 별도 설정창을 닫으면 실행이 끝납니다. 설정·로그는 해당 창 메모리에만 있습니다. 브라우저의 타이머 지연이나 PC 절전은 조회를 늦출 수 있습니다. 중지는 이미 시작한 새로고침을 되돌리지는 않습니다.

조회 간격은 직전 조회 완료 후 기다리는 시간입니다. 실행 중 변경은 다음 대기부터 반영됩니다. 오류가 나면 설정된 추가 대기 후 조회 간격을 거쳐 다시 시도합니다. 동일 코레일 탭은 한 설정창에서만 실행됩니다. 조회 조건이 달라지거나 선택한 열차가 사라지면 멈추며, 없는 열차를 매진으로 처리하지 않습니다. 더보기 자동 로딩은 아직 없으므로 현재 로드된 열차만 선택합니다.

## 설치

1. **평소 쓰는 일반 Chrome** 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다. 이것은 확장프로그램 설치 설정이며 **F12 개발자 도구를 여는 동작이 아닙니다.**
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 아래 폴더를 선택합니다. 파일이 아닌 **extension 폴더**입니다.

```text
C:\Users\bill7\OneDrive\문서\ChatGPT\기차예매 매크로\extension
```

5. Chrome 우측 퍼즐 모양 아이콘에서 **코레일 목록 확인**을 고정합니다.

Chrome 공식 설치 안내: https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked

## 확인

1. 정상 Chrome에서 코레일 열차를 직접 조회합니다.
2. 목록이 보이는 탭에서 **코레일 목록 확인** 아이콘을 누릅니다.
3. **현재 목록 읽기**를 누릅니다.
4. 날짜·구간과 07:47 / 08:20 항목 등이 표시되는지 확인합니다.
5. **진단 파일 저장**을 누르고 내려받은 `korail-public-snapshot-….json` 파일을 작업 대화에 첨부합니다. 팝업의 **저장할 내용 확인**에서 동일한 내용을 먼저 볼 수 있습니다.

시크릿 창에서 쓰려면 확장프로그램의 **세부정보 → 시크릿 모드에서 허용**을 켜야 합니다. 일반 창에서 정상 조회된다면 일반 창으로 확인하면 됩니다.

팝업을 닫으면 읽었던 내용은 사라집니다. 다시 열고 읽기 버튼을 누르면 됩니다. 코드를 업데이트한 경우 `chrome://extensions`에서 이 확장프로그램 카드의 새로고침 버튼을 누르세요.

## 0.2 갱신 시험

1. `chrome://extensions`에서 **코레일 목록 확인** 카드의 새로고침 버튼을 누릅니다. 팝업 위쪽에 **0.2**가 보이면 업데이트된 상태입니다.
2. 코레일 결과 탭에서 팝업을 열고 **현재 목록 읽기**를 누릅니다. 열차번호·출발시각·등급별 상태를 구분해 보여줍니다.
3. **갱신 1회 시험**을 누릅니다. 현재 코레일 탭을 한 번 새로고침합니다. 대기 시간은 기본 30초이며 1~120초로 변경할 수 있습니다.
4. 확인 중에는 팝업을 열어 둡니다. 새 문서에서 같은 조건의 목록이 보이면 결과를 표시합니다. 기존 문서를 다시 읽은 것만으로 성공 처리하지 않습니다.
5. 성공 또는 실패 문구가 나온 뒤 **진단 파일 저장**으로 저장해 공유합니다. 파일에 `refreshProbe` 결과가 포함됩니다.

관심 시각은 현재 로드된 목록 안에서만 찾습니다. 08:00 이후 목록에 07:47편이 없으면 ‘현재 로드된 목록에 없음’으로 표시하며 매진으로 추정하지 않습니다. 두 목표편을 함께 보려면 사이트에서 07:00 이후로 조회하면 됩니다. 이 입력은 현재 표시를 위한 것으로 자동 예약 대상 설정은 아닙니다.

‘좌석 표시’는 화면상 일반실/특실 요금이 표시되어 있다는 뜻입니다. 실제 예약 성공을 보장하지 않습니다. 입석+좌석은 일반 지정석 가능 상태와 구분합니다.

## 읽는 범위

- `https://www.korail.com/ticket/search/list`의 공개 조회 조건과 `.tckWrap` 열차 결과 영역만 읽습니다.
- 목록 읽기는 페이지를 변경하지 않습니다. 갱신 시험 버튼은 현재 탭을 한 번 새로고침하며 예약·결제 버튼이나 더보기는 누르지 않습니다.
- 쿠키, 저장된 로그인 정보, 숨겨진 입력값, 결제 화면, 요청/응답은 읽지 않습니다.
- 진단 파일에는 공개 텍스트와 제한된 구조(태그·클래스명)가 들어갑니다. URL의 query, DOM ID, data 속성, 이벤트 핸들러는 제외합니다.
- 모든 데이터는 팝업 또는 별도 설정창 메모리에 있으며, 진단 저장 버튼을 누를 때만 JSON 파일로 내려받습니다.

권한은 `activeTab`과 `scripting`만 사용합니다. 상시 사이트 접근, debugger, 네트워크 감시, 백그라운드 실행 권한은 없습니다.

## 현재 검증 범위

사용자가 제공한 2026-10-01 스냅샷으로 실제 목록 읽기, 2026-10-04 스냅샷으로 1회 갱신 후 같은 조건의 목록 읽기를 확인했습니다. 이어 사용자가 좌석이 없는 상태에서 0.3 반복 조회가 정상 작동한다고 확인했습니다. 공개 행 fixture를 이용해 파서·반복 제어·설정창을 모의 화면에서 검증합니다. 실제 좌석 발견 시 정지와 예약·결제는 아직 실사이트에서 검증되지 않았습니다.
