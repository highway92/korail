# 실사이트 화면 관찰 기록

2026-10-01, 공개 코레일 웹 화면을 Chrome/Playwright에서 직접 조회했다. 첨부 스크린샷은 흐름 설명 자료이며 DOM selector의 근거로 취급하지 않는다.

## 확인한 부분

- 일반 조회 주소: `https://www.korail.com/ticket/search/general`
- 조회 결과 주소: `https://www.korail.com/ticket/search/list`
- 출발역/도착역 선택 link, 역명 link, `txtGoStart`, `txtGoEnd` 입력값.
- `출발일` link → 날짜 선택 dialog → `.datepicker`의 `p.date`로 월 구분 → 날짜 link → `적용`.
- 미래 날짜 선택 후 `00시 이후 출발` 표시. `#startDate`에서 적용값 확인.
- `열차 조회` button 클릭 뒤 결과 주소 이동.
- 결과 조건: `#labelstart`, `#labelend`, `#startDate`.
- 결과 영역: `.tckWrap > ul`. 빈 결과는 `해당 스케줄에 운행하는 열차가 없습니다.` 문구.
- 공개 홍보 dialog의 `창닫기`만 처리. 미확인 확인창을 일괄 승인하지 않는다.

## 남은 확인

자동화 Chrome에서 10월 9일 용산→정읍과 10월 2일 서울→부산을 조회했으나 모두 빈 목록을 표시했다. Headless와 화면 표시 Chrome에서 재현했다. 사용자는 일반 브라우저에서 로그인 없이 열차 목록이 보인다고 확인했다. 따라서 이를 실제 운행 없음이나 매진으로 판정하지 않는다.

전용 프로필 Chrome을 열고 사용자의 수동 조회 결과와 비교 중이다. 실제 열차 행이 확보되기 전에는 selector를 추정하여 예약하지 않는다. 결과 로딩/오류 상태와 더보기 처리를 확인한 후 반복 조회를 연결해야 한다.

예약·카카오페이 요청/미결제/완료·발권 화면의 DOM, popup/iframe 구성, 정확한 문구와 예약 식별자는 아직 관찰하지 못했다. 엔진은 모의 사이트로 테스트했고 실사이트 거래 연결은 비활성화했다.

## 공개 조회 실패 진단 (추가)

사용자가 조건 차이와 무관하게 전용 브라우저에서만 목록이 비는 것을 확인했다. 이후 조건 비교를 중단하고 요청 상태를 조사했다.

- Playwright가 실행한 화면 표시 Chrome: 공개 조회 중 `www.korail.com/web_s/[동적 경로 생략]` XHR에서 HTTP 500. `Uncaught Error` 페이지 오류도 관찰. 해당 오류와 500의 인과관계는 아직 미확인.
- Chromium 보안 샌드박스를 활성화한 비교: 같은 HTTP 500 재현. 따라서 샌드박스 옵션 변경으로 해결되지 않음.
- 새 임시 프로필의 Chrome을 일반 프로세스로 실행한 후 공식 CDP 연결: 역시 HTTP 500. 이 실행에서는 최종 날짜가 요청한 날짜와 달라져 완전한 대조 실험으로 취급하지 않음. CDP 전환을 제품에 적용하지 않음.
- HTTP 500만으로 코레일의 자동화 차단이라고 확정할 수 없음. 새 프로필/세션 문제와 자동화 연결의 영향을 구분하기 위해 사용자의 일반 Chrome 시크릿 창 조회 여부를 요청함.

제품 개선: 공개 조회에서 HTTP 실패를 관찰하면 매진·운행 없음으로 취급하지 않고 별도 오류로 표시한다. 탐색 엔진에서는 설정한 오류 대기/배수/횟수 제한을 적용한다. 조회 클릭 후 관찰된 결과 요청 응답까지 기다려 초기 빈 컨테이너를 결과로 읽지 않도록 변경했다. 실제 행 렌더링 완료 조건은 행 구조 확보 후 추가 검증이 필요하다.

제품 진단에는 HTTP 상태 숫자·요청 실패 횟수·페이지 오류 횟수만 보관한다. URL, 쿠키, 헤더, 요청/응답 본문, 로그인·결제 화면은 보관하지 않는다. 개발 진단 도구는 로그인하지 않은 공개 페이지에서 경로·상태를 기록하되 query와 동적 경로를 생략한다.

## 느린 조작 비교

사용자의 속도 가설에 따라 기본 Chrome 실행 조건을 유지하고, 초기 화면 표시 후 10초 대기·각 클릭 후 2초 대기를 넣어 공개 조회를 한 번 실행했다. 동일한 HTTP 500이 재현되었다. 따라서 단순 클릭 간격 부족만으로 원인을 설명할 수 없으며, 자동화 차단 여부는 여전히 미확인이다.

신규 설정 기본값을 클릭 후 2초, 조회 화면 진입 후 10초로 두고 상세 설정에서 변경 가능하게 했다. 저장된 기존 클릭 간격은 덮어쓰지 않는다. 역 선택 직후 실제 입력값 반영도 확인한다. 초기 대기는 조회 화면을 새로 열 때마다 적용되며 조회 간격(이전 조회 완료부터 다음 조회까지)과 별개다.

## 오류 내용과 진입 경로 확인

- 페이지 오류 메시지는 `only one instance of babel-polyfill is allowed`이며, 발생 파일은 네이버 로그인 SDK `static.nid.naver.com/js/naveridlogin_js_sdk_2.0.2.js`였다. 이를 조회 실패의 원인으로 간주하지 않는다. 정상 Chrome에서 같은 오류가 발생하는지는 아직 확인하지 못했다.
- HTTP 500 HTML의 제목은 ‘코레일 승차권예매’, 화면용 안내 문구는 주소가 잘못 입력되었거나 변경/삭제되어 요청한 페이지를 찾을 수 없다는 내용이었다. 자동화 차단을 직접 명시한 응답은 관찰하지 못했다.
- 코레일 홈 `/ticket/main`을 먼저 열어 로드 완료 후 10초 기다리고 일반 조회 화면으로 이동한 실험에서도 같은 HTTP 500과 안내 문구가 재현됐다. 단순 홈 진입 초기화 누락 가설은 이 실험으로 뒷받침되지 않았다.
- 현재 연결 도구에는 정상 Chrome 탭이 노출되지 않아 작동하는 브라우저의 요청과 직접 비교할 수 없다. 사용자에게 일반 Chrome 시크릿 창에서의 수동 조회 결과를 요청했다. 기존 세션/프로필 영향과 자동화 환경의 영향을 구분하기 위한 다음 증거다.

진단 도구는 로그인하지 않은 새 프로필에서 페이지 오류 메시지·발생 파일과 실패 응답의 화면용 안내 문구를 추가로 수집한다. 동적 경로와 긴 토큰 문자열을 가리고 스크립트/스타일 및 응답 원문은 보관하지 않는다. 현재 조회 장애는 해결되지 않았으며, 새로운 확인 없이 자동화 관련 실행 플래그를 계속 바꾸지 않는다.

## 일반 Chrome 확장프로그램 검증으로 전환

- 사용자가 시크릿 Chrome에서도 비로그인 상태의 열차 목록이 정상적으로 표시된다고 답변했고 07:47/08:20 행이 보이는 스크린샷을 제공했다. 기존 로그인 쿠키가 반드시 필요한 현상은 아닌 것으로 보인다.
- 별도 프로필의 일반 Chrome을 0이 아닌 로컬 디버깅 포트로 실행하고 Playwright CDP 연결한 비교에서도 HTTP 500이 재현됐다. 이 방식은 제품에 적용하지 않았다. 재현 도구는 `tools/probe_normal_chrome.py`다.
- 사용자는 F12 진입 시 화면이 멈추고 JavaScript를 꺼도 진행되지 않는다고 보고했다. 개발자 도구 기반 비교 요청을 중단했다. 보호 동작의 정확한 원인은 확정하지 않았다.
- 사용자가 정상 브라우저의 확장프로그램 방식으로 접근하는 것을 승인했다. `extension/`에 activeTab+scripting 권한만 사용하는 읽기 전용 검증 버전을 만들었다.
- 확장프로그램은 현재 공개 목록 DOM을 읽어 텍스트와 제한된 구조만 보여주고 JSON으로 저장한다. 디버거·네트워크 감시·자동 클릭·외부 전송을 사용하지 않는다. 쿠키·숨김 입력·비공개 페이지는 읽지 않는다.
- 모의 DOM의 정보 범위/숨김 정보 제외/팝업/JSON 저장 검증은 `tools/smoke_extension.py`로 수행한다. 이는 실사이트 확장프로그램 성공 검증과 다르다. 사용자가 정상 Chrome에 설치한 후 실제 목록 읽기 결과를 받아야 다음 단계로 진행할 수 있다.

## 정상 Chrome 목록 읽기 성공 및 파서 연결

사용자가 `korail-public-snapshot-2026-10-01T04-37-30-165Z.json`을 제공했다. 2026-10-09 용산→정읍, 08:00 이후, 총 1명의 목록 10편이 읽혔고 `truncated: false`였다. 08:20의 411편은 일반실·특실 매진, 07:47편은 해당 로드 목록에 없었다. 이는 파일 시점의 표시 상태다.

실제 구조는 `.tckWrap > ul > li.tckList` 안에 `.info_inner`, `.num`, `.data_box h3.txt_bk`와 두 `.price_box`가 있는 형태다. `sold_out`은 매진, `gen`/`spe`와 등급·요금 표시는 일반실/특실, `yms`와 ‘입석 + 좌석’은 입석 포함으로 구분했다. `sold_out_soon`의 ‘특실(매진임박)’을 매진으로 오인하지 않는다. 신규 파서는 날짜·구간·열차번호·출발시각을 식별자로 묶고 경로 불일치·중복·잘린 데이터는 거절한다.

전체 10편 파싱과 그중 4가지 상태의 실제 공개 구조 fixture 테스트를 통과했다. 0.2 팝업은 관심 시각 표시와 ‘갱신 1회 시험’을 제공한다. 사용자가 버튼을 누를 때만 탭을 한 번 새로고침하고, 새 문서인지 및 기존 조회 조건 유지 여부를 확인한다. 대기시간은 1~120초로 설정한다. 모의 제어/팝업 검증은 통과했지만 실제 갱신과 반복 조회·예약·결제는 아직 검증되지 않았다.
